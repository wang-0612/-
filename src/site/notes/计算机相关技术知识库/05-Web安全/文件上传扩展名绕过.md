# 文件上传扩展名绕过

> [!warning] 合规声明
> 本文操作均在 upload-labs 靶场完成，仅用于授权教学与防御学习。

## 黑名单与白名单

| 类型 | 定义 | 示例 |
|------|------|------|
| **黑名单** | 列表中记录的内容被限制或禁止 | 禁止上传 `.asp`、`.php`、`.aspx`、`.jsp` |
| **白名单** | 只有列表中的内容才允许执行 | 只允许 `.png`、`.jpg`、`.gif` |

> [!important] 黑名单天生不完整
> 黑名单的思路是"列出所有危险扩展名"，但解释器支持的扩展名、系统特性、解析规则远比列表多，因此**极易被绕过**。安全实现应优先使用白名单。

## 绕过手法总览

| # | 手法 | 关卡 | 平台 | 核心原理 |
|---|------|------|------|---------|
| 1 | 特殊扩展名 | Pass-03 | Linux | 解释器支持其他 PHP 后缀 |
| 2 | .htaccess | Pass-04 | Linux/Apache | 改变目录的解析规则 |
| 3 | 大小写 | Pass-06 | Linux | 过滤未统一大小写 |
| 4 | 空格 | Pass-07 | Windows | 系统自动去除文件名尾部空格 |
| 5 | 点号 | Pass-08 | Windows | 文件名末尾的点不被解析 |
| 6 | `::$DATA` | Pass-09 | Windows | NTFS 数据流不检查后缀 |
| 7 | 点 + 空格 + 点 | Pass-10 | Windows | `deldot()` 遇到空格停止删除 |
| 8 | 双写 | Pass-11 | Windows/Linux | 替换函数只执行一次 |

## 1. 特殊扩展名（Pass-03）

由于历史原因，部分解释器可能支持符合正则 `/ph(p[2-7]?|t(ml)?)/` 的后缀，例如：

```text
php  php2  php3  php4  php5  php6  php7
pht  phtml  shtml  pwml  phtm
```

网站只过滤 `.asp|.aspx|.php|.jsp` 时，可以尝试这些后缀：

1. 将木马 PHP 文件扩展名改成 `.phtml`
2. 直接上传 `.phtml` 文件
3. 上传成功后访问，若服务器仍按 PHP 解析则成功

## 2. .htaccess 绕过（Pass-04）

### 原理

`.htaccess`（Hypertext Access，超文本入口）是 Apache 的**分布式配置文件**，用于在特定目录中放置指令，作用于该目录及其所有子目录。管理员可以通过 `AllowOverride` 控制是否允许使用。

在文件上传中，`.htaccess` 的最大作用是**让任意类型的文件被当作 PHP 解析**，该文件在 Apache 中默认启用。

### 利用步骤

1. 准备一个 `a.htaccess` 文件，内容：

```apache
SetHandler application/x-httpd-php
```

2. 使用 Burp 抓包上传该文件，并把文件名改成 `.htaccess`
3. 将 PHP 木马改成任意扩展名，如 `shell.ppp`，直接上传
4. 访问 `shell.ppp`，解析成功

> [!note] 适用条件
> 该手法依赖 Apache + 允许 `.htaccess` 生效。Nginx / IIS 环境不适用。

## 3. 大小写绕过（Pass-06）

网站在过滤扩展名时，如果没有**先把字符串统一大小写再比较**，可以通过修改扩展名大小写绕过。

```text
shell.phP
shell.PHP
shell.Php
```

Pass-06 中，网站黑名单没有验证大小写，将 PHP 木马扩展名改为 `phP` 即可直接上传解析。

## 4. 空格绕过（Pass-07）

### 原理

在 Windows 中，文件名末尾如果有空格，系统会**默认去除**：

```text
"example.php    "  →  "example.php"
```

但服务器做字符串匹配时，`".php    "` 与 `".php"` 匹配不成功，于是绕过黑名单。

### 操作

1. 上传 PHP 木马，使用 Burp 抓包
2. 修改文件名，在末尾加上一些空格（如 `shell.php `）
3. 上传成功并解析

> [!warning] 仅限 Windows
> 该特性依赖 Windows 文件系统对尾部空格的处理，Linux 不适用。

## 5. 点号绕过（Pass-08）

在 Windows 中，**文件名最末尾的点不会被解析**：

```text
shell.php.  →  shell.php
```

Pass-08 中，网站黑名单没有去除末尾的点。抓包后在文件名末尾加一个点，即可上传并解析。

## 6. `::$DATA` 绕过（Pass-09）

### 原理

在 Windows 中，如果文件名加上 `::$DATA`，系统会把 `::$DATA` 之后的数据当成**文件流**处理，不会检测后缀名，同时保留 `::$DATA` 之前的文件名。

```text
a.php::$DATA  与  a.php  等价
```

Pass-09 中，黑名单没有检测 `::$DATA`：

1. 上传 PHP 木马，Burp 抓包
2. 修改文件名，末尾加上 `::$DATA`
3. 上传成功；访问时去掉 `::$DATA` 即可

> [!note] 适用条件
> 依赖 Windows NTFS 的备用数据流（ADS）特性，仅 Windows 环境有效。

## 7. 点 + 空格 + 点（Pass-10）

### 原理

PHP 中的 `deldot()` 函数会删除字符串中的点，但检测到末尾的第一个点后会删除，并继续检测；**如果遇到空格则停止删除**。

因此可以构造「点 + 空格 + 点」：

```text
shell.php. .
```

过滤函数删除第一个点后遇到空格停止，剩余部分在 Windows 文件系统中又被处理为 `shell.php`，从而绕过。

### 操作

Pass-10 中，网站黑名单使用 `deldot()` 删除末尾的点：

1. 上传 PHP 木马，Burp 抓包
2. 修改文件名，末尾加上「点 空格 点」
3. 上传成功并解析

## 8. 双写绕过（Pass-11）

### 原理

PHP 的 `str_ireplace(find, replace, string, count)` 用于替换字符串中的字符（不区分大小写），但**只替换一次**。如果后端验证扩展名时没有递归替换，就可以用双写扩展名绕过。

```text
shell.pphphp  --(替换一次 "php" 为空)-->  shell.php
```

Pass-11 中，网站黑名单没有递归删除扩展名：

1. 上传 PHP 木马，Burp 抓包
2. 修改扩展名为 `.pphphp`
3. 上传成功，可直接访问解析

> [!warning] 不要写错
> 不要改成 `phphpp`——替换后扩展名会变成 `hpp`，无法解析。关键是让过滤删除一次后**恰好剩下 `php`**。

## 防御要点

| 措施 | 说明 |
|------|------|
| **白名单** | 只允许业务必需的扩展名 |
| **统一规范化** | 统一大小写、去除首尾空格和点、拒绝 `::$DATA` 等特殊字符 |
| **重命名** | 上传后随机生成文件名，彻底消除用户控制扩展名的机会 |
| **内容校验** | 文件头/魔数、图片二次渲染 |
| **上传目录禁止执行** | 无论上传什么文件都无法作为脚本运行 |
| **禁用 .htaccess 覆盖** | Apache 设置 `AllowOverride None` |
| **Web 根目录分离** | 文件放到独立存储或对象存储 |
